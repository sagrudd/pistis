# ADR 0002: Protocol signature suites

- Status: Accepted
- Date: 2026-07-24
- Owners: Protocol and mobile security

## Context

Pistis signatures must be verifiable offline in Rust and generated by keys
protected by Apple Secure Enclave and Android Keystore. The original charter
named Ed25519, but secure hardware support for Ed25519 is not consistently
available across the required mobile platforms.

## Decision

Protocol v1 uses COSE algorithm `ES256` (ECDSA over NIST P-256 with SHA-256) as
the mandatory mobile interoperability suite. Verifiers require fixed-width
COSE `r || s` signatures, validate curve points and algorithm identifiers, and
reject algorithm substitution.

`EdDSA` with Ed25519 may be registered later for software, service, or offline
keys. It is not a v1 mobile conformance requirement and must use a distinct
algorithm identifier and key-type policy.

Keys are identified by a collision-resistant digest of their canonical public
key representation. The precise identifier construction and cryptographic
implementation belong to EPIC-2 and must not change signed protocol fields.

## Consequences

- iOS and Android can generate non-exportable keys in their standard secure
  key stores.
- Rust verifiers can use mature, independently reviewed P-256 libraries.
- Implementations must handle ECDSA nonce generation safely inside platform
  APIs and reject malleable or incorrectly encoded signatures.
- This decision deliberately narrows the charter's Ed25519 preference for
  mobile keys while preserving a future software-key suite.

## Alternatives considered

- Ed25519 only: compact and deterministic, but not a reliable common
  hardware-backed mobile denominator.
- RSA-PSS: broadly supported but produces larger keys and QR payloads.
- Multiple mandatory suites: increases downgrade and interoperability risk
  before the first protocol is stable.
